# Audit event contract v1

`audit-event-catalog.json` is the single event-type/metadata-rule input; `tools/audit-contract/generate-schema.mjs` derives `audit-event.schema.json`. Existing taxonomy is preserved. Deferred types are listed in the catalog for explicit compatibility accounting but are not accepted delivered envelopes.

The schema is JSON Schema2020-12. Contract validation must register `auditMaxUtf8Bytes`, `auditEnvelopeBytes` and `auditLegacyTime`; generic validators that ignore them are insufficient. `audit-core::schema_validate` uses the repository-selected jsonschema0.55.0 engine with those keywords. `AuditEnvelope::validate` additionally requires source/resource/action/result, metadata/correlation and service-executor cross-bindings. A structural schema match alone is not a qualified Audit event. Raw envelope input is capped at32KiB before parse; legacy source wire at24KiB. Both raw constructors reject duplicate decoded member names at every object depth (including escaped aliases and identical values) before maps/canonicalization can discard evidence. Externally materialized JSON Values are not raw-admission proof. SQL pre-materialization admission remains a separate required boundary, not implemented by this crate.

Canonical digest algorithm `audit-json-v1` sorts object keys recursively, preserves array order and signed64 integer values and emits compact UTF-8 JSON. It is not advertised as a general-purpose RFC8785 encoder. Access-policy target type/ID must equal the Document/Folder resource; policy identity is separate metadata. Source legacy timestamp tuples reject mixed-sign offsets that the time library would normalize, while valid tuples and32-byte digest arrays retain their original values; envelope timestamps use UTC RFC3339. No independently generated replacement event ID or request correlation is allowed.

Compatibility: free-text reason-bearing variants remain quarantined with source evidence protected. Non-W3C legacy correlation is a separate `legacy_correlation_id`; it is never labeled as validated trace context. Publish intent references use `publish_operation_id`, preserving their meaning even in cancellation; they do not invent a missing cancellation operation ID. Current legacy rows have no request-ID field, so none is accepted as an attested legacy correlation. `serviceExecutor` remains distinct from the initiating actor. Actor kind remains unknown when the legacy producer did not attest it.

Evolution: incompatible required fields, meaning, canonicalization or metadata encoding require a new schema/canonicalization version and an explicit adapter/rollout. A new optional field/type is not automatically backward-compatible with an old closed validator: update and qualify readers before producers use it, retain old schema support and quarantine unknown future versions. No future Organization event vocabulary is reserved by this v1 catalog.

Conformance fixtures are synthetic. No real document/query/ACL/credential data belongs here. Schema/core tests do not qualify source SQL admission, database privileges, durable delivery, investigation, retention or recovery.

Management compatibility correction: normal `access_policy.changed` payloads are deferred even without a `reason` key, because the approved reason is absent from both that payload and the Management ledger. Only the explicit `bootstrap=true` Root Folder variant, non-null policy ID, policy_revision1 and positive access_revision is eligible. This does not reconstruct historical reasons or change producer code. See the Management compatibility amendment and its review receipt; a schema-valid event is not a claim that every producer contract is complete.
