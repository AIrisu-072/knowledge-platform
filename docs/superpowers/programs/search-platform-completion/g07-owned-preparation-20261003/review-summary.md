## 準備時の修正と限界

準備では各失敗の記録を上書きせずに保持しました。修正には、G06で公開済みの保留結果の有界な処理、アーカイブ・記録・識別情報に対する厳密な保護、固定された後処理用の余裕時間、曖昧さのない子プロセスマーカーの区切り、ソースに対応する新規バイナリの確認、同一呼び出し内の管理されたダウンロード転送、総ダウンロード時間を変えない30秒の接続余裕、実際の出力に基づくELFレポート上限、元のポーリング期限内で消失したビルド項目に対する同じビルドディレクトリの1回だけの再走査が含まれます。不完全なディスク使用量の集計と、確実に確認できた管理下プロセスの終了・回収は区別しました。

成功したビルドでは、GNU Makeが対応するパイプ方式のjobserverを使用しました。先行する一時的なinodeは特定されなかったため、以前のFIFOという説明は仮説のままです。後に観測した項目の消失は、それとは別のビルドファイルの競合でした。任意のinodeの受入、期限のリセット、実行時出力上限の緩和は導入していません。

独立したソースレビューにより、名前を指定した復旧2ケース、純粋テストの対象範囲、既存フィクスチャのAPI、必要な専用フィクスチャが利用できない場合に未検証であることを明示する動作が保たれています。すべての変更はテスト・準備作業の範囲内です。この記録によって、本番の依存関係・API・凍結済みの復旧仕様を新たに採用または変更したとは扱いません。

## 公開出力の最小化

当初の一括した機密性判定では、オフラインのPostgreSQL制御出力に含まれる認証関連のnonceを見落としていました。公式ソースから、これはログイン成功にそのまま使えるbearer tokenではないものの、クラスタ単位の模擬認証の秘密情報であると確認しました。認証情報を除外する共有許可に、この値は含まれません。そのため、公開コピーでは該当する出力1行だけを除外し、原出力のハッシュ・サイズと非公開原本を明示して保持しています。公開コピーのハッシュ・サイズは原本とは別に記録します。以前の機械的なストリームハッシュは引き続き非公開原本を示します。この修正によって、ソース、テスト結果、実行時の制限、保持しているクラスタは変わりません。原本や秘密情報の破棄・無効化は主張しません。

元の公開GOは撤回し、その後、英語の最小化候補だけが別途レビューでGOとなりました。53個のblobと正確な最小化treeはremoteに作成されていますが、`create_commit`は`user cancelled MCP tool call`で停止しました。refは`da5e7155db616c1df9a688a7043fc3b4730bb1a3`のままで、新headの公開やCI成功は未確認です。commit SHAは返されず、commitオブジェクトの作成成否は未確定です。15:27:40 UTCの読み取り専用照合では、refは旧head `da5e7155db616c1df9a688a7043fc3b4730bb1a3`のままでした。日本語版の意味保存レビューと公開可否の再判断は別途必要です。将来の公開は、最新のリモートheadと公開対象のtreeを照合してから行います。
