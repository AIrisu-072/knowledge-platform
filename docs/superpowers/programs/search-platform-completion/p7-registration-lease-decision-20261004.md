# P7-02 登録と共有Sourceリースの実装判断

状態：実装・ローカル対象検証・独立したソース限定レビュー済みです。実PostgreSQLのRED/GREEN、本番構成、全体受入は未確認です。本記録は、完成まで進める依頼の範囲で行った工学的判断であり、依頼者が以下のAPI詳細を個別承認したという記録ではありません。

## 保存する契約

- P6-S01の既存ポート、`SourceFence`、`SearchSourceLease`、エラー型を再利用します。`SourceRegistrationLedgerPort`を増やしません。
- DocumentとRemoteは一つの`PgPool`、既存`search_registration_serial`、`search_source_coordination`、`search_source_ownership`を使います。Searchの0001/0002/0003とDomainの番号は変更しません。
- `CompleteDesiredRegistrations::capture`による既存の全DTO・正規ダイジェスト検査を、ホスト正本との初回比較とコミット直前比較に再利用します。登録集合は当該名前空間の全テナントの完全集合です。テナント別Vecから公開カタログを作る入口は追加しません。
- 同じ配備改訂の異なる集合、改訂の逆行、削除済みSourceIdの別テナント・別種別での再利用を拒否します。DTO・可視性・登録改訂の変更と削除・再有効化は有効化世代とSourceフェンスを増やし、リースを失効させます。既存の現在キー・二つのダイジェスト・ポインター改訂は更新しません。

## 最小限のAPI調整

アプリケーションに、検証済み`SourceRegistration`からだけ発行する読み取り専用の`persistence_dto_v1`を追加します。全フィールドを持つJSONであり、JSONから登録や正本性を発行する逆変換はありません。`persistence_digest_v1`は、既存の名前空間別canonical encoderに単一Sourceの集合を渡すだけです。JSONBの物理表現をハッシュにしません。`matches_persisted_definition_v1`は、既存の可視性だけを除く比較と同じ意味で、完全なJSONビューを比較します。未知フィールドや欠落は一致しません。

`search-runtime`へ既存の`serde_json.workspace`参照を一つ加え、Cargo.lockの同パッケージ依存一覧に一行を加えます。解決済みパッケージの版・checksumは変えません。

凍結S02の`PostgresSourceAdmission::new(pool, source, ttl)`を無条件の公開入口にはしません。`PgSourceRegistrationLedger::source_admission(source, ttl)`だけを公開し、登録と同じpoolと否定ゲートを共有します。理由は、別構築したadmissionでは、登録コミットの応答不明やfutureのキャンセルで閉じた状態を共有できないためです。グローバルなpool対応表、第二の台帳、ゲートなしの迂回入口は追加しません。

## 応答不明とキャンセル

ゲートはDBの所有権の代わりではなく、DB検証に加えるプロセス内の否定条件です。初期状態は閉じています。Document/Remoteをそれぞれ正常に突き合わせると、確認済みbitが残り、両方が揃って初めてSourceリースを取得できます。通常の片側更新は、他方の確認済み状態を保持します。

登録変更を開始する前にゲートを閉じます。コミット成功応答後だけ開き直します。エラー、`CompletionUnknown`、futureのdrop/abortでは閉じた状態が残ります。その後は両名前空間を再照合し、同じホストの現行改訂・digest・全DTO、保存行と現在の有効化状態を確認してから配送許可を再開します。更新世代stampをDB読み取り・取得・更新の前後で比較するため、閉鎖後に開き直す競合も、途中の古い成功として返しません。

SQLSTATE `40001`・`40P01`・`55P03`の確認済み中断だけは、同じ期待登録集合でトランザクション全体を最大3回試します。ホストとDB条件は毎回読み直します。通信・コミット応答不明、制約違反、カウンターのオーバーフローはこの再試行へ入れません。ゲートの世代stampが尽きた場合も、値を再利用せず閉じたまま維持します。

独立したレプリカは共有DBの直列化・フェンス・所有権を毎回検査します。プロセス内ゲートが別プロセスのメモリを共有するとは主張しません。本番ホストの全テナント列挙、同じホスト改訂に属する二名前空間の公開、起動走査、API/worker有効化は、凍結済みR01P/R02/P7-12の未完了ゲートです。

## 検証の境界

既存pending登録草案を実行対象へ移し、共有の既存PostgreSQLフィクスチャを使います。独立接続の2/4/8競合は接続試験として命名し、OSプロセス資格とは呼びません。コミット中キャンセルのケースは、合成DB内の遅延トリガーと一つのadvisory lockだけでコミットを止め、キャンセル後の閉鎖と両名前空間の再照合を調べます。closed poolの純粋ケースは通信なしの失敗分類であり、実際のコミット結果不明の実証ではありません。

追加の取得・更新ケースは、合成DBの遅延制約トリガーが`RETURNING`後の暗黙コミットでエラーを返す状況を扱います。取得は実`DeliveryRunner`と最小のclaim回数記録で0回を検査し、更新は`Updated`を返さないことを検査します。通信途中の応答喪失やコミット済み状態の不明を再現したという主張はしません。

ローカルDB、Docker、ソケット、リスナーは実行しません。過去の所有権SQL/P4レビューは設計・由来の証拠であり、新しい登録・リース実装の適合を証明しません。新しいRustコード、純粋ケースと対象コンパイル、承認済みGitHub Ubuntu・公式PostgreSQL18.6・架空データでの実DBケース、正確なソースに対する独立レビューを分けて記録します。Graph、publisher、pin、GC、マージ、デプロイ、本番接続は本変更に含めません。
