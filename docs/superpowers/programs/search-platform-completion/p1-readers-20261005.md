## 判断

所有者は2026-10-05、Searchの残作業を効率よく完了し、検証を過剰にしないよう指示した。これを受けて、P1-Q01を次の範囲で閉じる。

- 隔離PoC（`experiments/search-extraction-poc/`）は固定合成corpus 45件をLinux・macOSの両方で再資格し、全形式で独立oracleと一致した。[qualification.md](../../../../experiments/search-extraction-poc/qualification.md)
- 使用する依存（`zip 8.6.0`、`quick-xml 0.42.0`、`encoding_rs 0.8.41`、`csv 1.4.0`、`html5ever`/`markup5ever_rcdom 0.39.0`、`pdfium-render 0.9.4` + PDFium 7881、`lopdf 0.45.0`）は、DSIで既に**SELECTED**としてworkspaceにpin済みである。root lockに新しいpackageは加わらない
- 本番readerはPoCの**資格済み構造subsetだけ**を`Supported`/`Partial`にする。subset外の構造、位置を証明できない省略、暗号、未知codec、上限超過はすべてUnit 0の`Unsupported`か型付き永続失敗にする。読み取れる範囲を推測で広げない

独立した再レビュー、一般corpus、1/10/50 MiB級の実測は今回の範囲外とし、未実施として残す。Linuxの隔離sandboxは既存の`runner_isolation`がhosted CIで確認する。

## 実装（`crates/search-extraction-worker/src/readers/`）

| Task | 形式 | locator | 省略と失敗 |
| --- | --- | --- | --- |
| I03 | Text（UTF-8／BOM、Windows-31J）、CSV（UTF-8・comma明示）、HTML | 物理行の半開区間、`(record, field)`、全child indexの`text_node_path` | 不正encoding、曖昧dialect、script・style・hidden等の動的可視性はUnit 0 |
| I04 | DOCX、XLSX、XLSM、PPTX | `BodyBlock→Row→Cell→CellBlock`、絶対`(row, col)`、slide順のshape path | header・footer・notes・VBA・chart・式セルは物理位置付き省略で`Partial`。OPC不一致、DOCTYPE、未知blockはUnit 0 |
| I05 | PDF、明示ZIP | PDFium文字indexの半開区間、member chain + inner locator | 複数pageの読み順、画像、未知operatorはUnit 0。ZIPは登録済みcomposite profileのnodeだけで振り分け、未登録member・未使用node・悪いleafで全体Unit 0 |

workerはPDFiumのpinを検査し、sandboxを閉じる**前**にlibraryを読み込む（DSIと同じ順序）。sealの後で各readerを実行する。全readerは15種のbudget keyを`BudgetMeter`で数え、上限超過を`ResourceLimit`の`Unsupported`にする。ResolveLocatorsは全体を再走査して、要求されたlocatorだけを要求順に返す。

## 検証

`cargo test -p search-extraction-worker` の受入試験15件（`readers_textual` 5、`readers_ooxml` 5、`readers_pdf_archive` 5）が手元で成功した。各試験は、readerが出したreportを本番の`validate_worker_report`でも検査する。PDF試験は固定PDFiumを`PDFIUM_DYNAMIC_LIB_PATH`で要求し、未設定ならskipせず失敗する。strict Clippyとrustfmtも成功した。

hosted CIの`rust-test`は、同じ試験をLinuxの固定PDFiumで実行する。Source host側の検証（S02）、manifest（B01）、索引（E01）以降は別のTaskで実装する。
