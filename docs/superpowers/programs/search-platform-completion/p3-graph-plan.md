# P3 Durable Typed HyperGraph Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` or `superpowers:executing-plans` task by task. Each task has a focused RED/GREEN cycle and an independent read-only review. This Completion Program already authorizes PoC, selection and implementation; no intermediate human approval is added. Repository dispatch/checkpoints use `orchestrate` → `toolbox-context` where available.

**Goal:** Select a measured durable graph backend, then build a lossless typed n-ary Graph generation adapter with current access, guarded incremental updates and restart-safe P3/P6/P7 coordination.

**Architecture:** An isolated three-backend PoC uses one deterministic corpus and the existing `search-graph-memory` semantic oracle. Only after the measured selection, a durable adapter owns Graph rows/bytes while `search-runtime` owns the one Source pointer, build guards, evaluation pins and guarded GC in one database transaction. Document Source supplies authoritative snapshot-bound mappings; P7 binds the durable reader to a server-issued evaluation lease before it can reach Discovery.

**Tech Stack:** Rust 2024 / 1.98.1; current `search-core`, `search-application`, `search-graph-memory`, SQLx 0.9 workspace, PostgreSQL `18.6-bookworm` image; PoC-only `redb =4.3.0`, Neo4j Community `2026.09.0` image and community `neo4rs =0.8.0` driver. Exact image digests and transitive dependencies are recorded from the executed PoC lock/container inspect, not assumed here.

**Spec:** [`p3-graph-freeze.md`](p3-graph-freeze.md), composed in this order from `p3-graph-design-revision-1.md` SHA-256 `ba9e8616d9dd8fc569280f20956c841929155366fa30246dadee0f0c73e8aa59`, `p3-graph-build-guard-amendment.md` SHA-256 `4f4597622f2053a7a782c5f0bf7704681c5542ed589d0b4fc3612ffa01595ab0`, and `p3-graph-cleanup-order-correction.md` SHA-256 `e0754819b37b4fc7eaf9cf1104ec634ed15549f520df2e1f25d45b1d8951d691`; independent GO `p3-graph-build-guard-review.md` SHA-256 `afe2fcd86688c741098480c72c44e7463217d509ae90da28743d5c9153cfc783`. ## Global Constraints

- A `TypedRelationInstance` is one n-ary edge. Source-local `(source_id,generation_id,resource_id/relation_id)` keys, all participant roles, namespace, qualifier `TypedValue` including `List` order, temporal instant **and offset**, authority, provenance, evidence refs and path evidence are lossless. `AccessProjection` is never final authority.
- Full and incremental builds from the same Source snapshot produce the same canonical Graph content digest, hit order, paths and evidence. `ProjectionGenerationManifest.digest` stays projection-only; Graph content, Source mapping and bundle digests occupy distinct fields.
- Durable stage accepts only `PersistentResource` and `PersistentDiscoveryMetadata`. `SessionOnly` / `NoRetention` remote data never enter this backend; remote outage/miss is never a deletion proof.
- The PostgreSQL incidence schema is provisional until P3-P04 selection. PoC crates and lockfile are isolated under `experiments/search-graph-poc/**`; never add `redb`, `neo4rs` or a Graph product dependency to root Cargo before selection and license/security review.
- P6-I03 owns physical `search_source_coordination` as defined by `crates/search-runtime/migrations/0001_search_source_coordination_v0.sql`, with exactly one current pointer and `build_fence_seq`. P3 creates **no second Source pointer**. P7 owns its transaction-bound mutation, pin and GC adapter. Any P3/P6/P7 combined transaction locks outbox event if present → Source row → generation rows by key → build guards by target key → evaluation leases by ID → Search receipt. Source-less batch uses generation → guard only and never later takes Source lock.
- PostgreSQL Graph rows use the separate additive `crates/search-graph/migrations/0001_search_graph_v1.sql` and Search-owned role/schema. Do not edit Document authoritative migrations or existing Source truth. READY and its binding/children are immutable by database grants/triggers, not just Rust checks. `ON DELETE RESTRICT` child/guard FKs remain.
- P7 is the only public owner of `publish_if_current`, `pin_current`, lease renewal/release, `retire_unpinned` and `discard_unpublished`. P3 isolated adapter exposes no READY retirement port. External requests cannot self-issue a generation/evaluation pin; Query returns only after a DB-clock lease recheck.
- Full/copy/delta/validation use one versioned, length-framed canonical encoder. Incremental copy takes a live base+target build guard before its first batch and checks token/fence, immutable base receipt, DB expiry and committed cursor in every batch and before commit. Expired handles cannot be revived.
- No customer data, live credentials/endpoints, merge, deploy or production migration. New production dependency, alternative non-PG publication protocol or legal/license blocker follows the frozen Hard Stop boundary. A candidate's PoC failure does not silently select PG.
- Local focused commands use `CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_TEST_DEBUG=0 CARGO_INCREMENTAL=0 CARGO_BUILD_JOBS=2`; measure free disk before container/build, run backends sequentially, retain at least 3 GiB free, and remove only this PoC's disposable containers/volumes after preserving measurements. Reuse local PG 18.6 image. A final broad gate runs once after material integration, not after every task.

### Task protocol and gates

Each task: write named assertion first; run the listed focused command and preserve intentional RED; implement the exact interface; rerun to GREEN; run focused strict Clippy/fmt if Rust changed; request independent read-only review; commit the task after review. For tests that need a service, use disposable local PG/Neo4j and independent processes/pools. If a failure is environment-only, record it as `UNMEASURED`, fix the fixture or reduce to the predeclared bounded corpus, and retry once; never call a skipped candidate PASS. Execute P00–P04 first, then G01–G05, C01, G06–G08, C02–C04 and D01–D02; G04 may use a test mapping validator and G07 a test lease verifier until G05/C04 supply the real adapters. `P3-P04` must record selection before G03 production backend code. If a non-PG backend wins, report the frozen-contract Hard Stop to the parent, retain G01/G02 domain work, and require an independently reviewed atomic publication/pin/guard/GC amendment before non-PG production code.
