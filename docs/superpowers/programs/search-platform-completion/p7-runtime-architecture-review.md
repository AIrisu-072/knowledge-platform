## Freeze を止める指摘

1. **[P2] 全 tenant の host 登録正本を production factory がどの adapter から得るか未確定。** 設計:27,34 は両 namespace の complete snapshot を要求するが、計画 R01/R02:23–33 は `HostRegistrationSnapshotPort` の実 adapter、全 tenant 列挙の証明源、P7-02 SQL ledger と P5-08 API factory の sole owner を指定しない。P4 独立再審査:13–16,44 もこの物理配線を P7 未判定と明記する。現行 `source_registration.rs:705–710,817–827,1114–1145` の ledger/capture/catalog port はすでに async なので、同期 shim や `block_on` は不要。`R02` の明示的な構築手順として、trusted host authority から Document/Remote の**全 tenant** inventory と revision/digest を取得し、P7-02 の `PgPool` backed `SourceRegistrationLedgerPort` で各集合を照合してから `SourceRegistrationCatalog::try_new` を `.await` し、成功前は listener/claim を閉じることを固定する。host 側 completeness を型名や候補 map 自体から推定せず、部分 tenant、片 namespace 欠落、stale revision、commit 応答不明、restart 後の不一致を実 PostgreSQL・別接続の R02 named startup tests に入れる。P7-02 が SQL adapter、P5-08 が四 route factory、R02 が host authority injection と組立てを所有するよう、重複なく task 入力/出力を明記する。
2. **[P2] Audit の runtime component は producer と配送の責務が未接続。** 設計:71 と計画 R04:41–45 は必須 event の同一 transaction 生成と Audit Store delivery retry を約束する。一方、P6 設計:12,19 は `audit_outbox_events` の配送/ack を明示的に対象外とし、R04 は event class policy、transaction owner、Audit outbox reader/settler、別 role と idempotent destination の producer または実装 task を指定しない。`spec/operations/observability-audit-requirements-v0.md:540–566,570–597,739–751` に従い、既存 Document Audit producer をどの port で消費するか、Search 管理操作/検索高量 event の採否を誰が決めるか、必須 event の transaction-bound outbox 作成、独立配送の retry/DLQ/ack/閲覧権を R04 の task か明示的な accepted capability alias に割り当てる。実 DB で Audit INSERT 失敗時 rollback、Audit Store 停止後の別経路再送、P6 Domain ack と Audit ack の非混同を named test とする。live Audit Store 選定や credential 値は今決めなくてよい。
3. **[P2] telemetry と診断の出力 field allowlist が retention mode ごとに閉じていない。** 設計:67–71 は restricted trace に evaluation/need/generation 等の ID と stage/count を許すが、`NO_RETENTION` 時に何を抑止するか、public health、管理診断、config/debug、log、metric、trace、Audit の各 sink でどの field を出せるかを固定しない。計画 R04:43–45 の「payload absent」だけでは provider 由来 candidate ID、digest、具体 gap、Graph/probe/receipt、response bytes や hidden Source count を error/timeout/buffer 経路で記録する実装を排除し切れない。規範 SD-O1/O2（`spec/operations/observability-audit-requirements-v0.md:1068–1080`）に沿って sink 別の typed allowlist と default deny、actor-visible 境界、`NO_RETENTION` の per-call provider-derived attribute 抑止、SecretRef/secret 値の全 sink 禁止を R04 に明記する。合成 sentinel を使い success/error/cancel/disconnect/deadline、exporter buffer flush/drop、shutdown 後に全 sink と保持 handle を捕捉する test を追加する。P4/P5 の二 lease と socket 送出完了条件は alias として再利用する。
4. **[P2] OTLP transport の未選定 PoC gate を R04/R06 が通過してしまう。** `spec/selection/library-tool-selection-v0.md:259–264,969` は OTel API/SDK/exporter を選定済みとする一方、HTTP/protobuf 対 gRPC の transport を `POC REQUIRED` とし、そのまま production dependency へ追加することを禁止する。計画 R04:43–45 は local OTLP receiver を使い、R06:53–57 は image 化するが、transport 比較・採択 receipt・root dependency gate を task に持たない。R04 の production transport 依存追加前に隔離 PoC で両候補の dependency/ライセンス・Collector 相互運用・停止時 bounded buffer/drop・必要性能を比較し、選定記録と version/feature pin を normative writer が更新する手順を追加する。選定されるまで adapter port と実装を分離し、R06 は未資格 transport を含む image を拒否する。具体 exporter API の是非はこの静的レビューで判定しない。
5. **[P2] R07 の負荷入力軸と実行予算が不足し、R08 の SLO 提案を外挿できない。** 設計:75–77 と計画 R07/R08:59–67 は小・中・大、同時数、latency/RSS/disk/fanout の測定を挙げるが、各 run の **Source 数（tenant/Document/Remote）、Document/Unit/Graph 関係数、request/provider payload bytes 分布、Remote fanout、HTTP と worker の concurrency、backlog** を制御入力として記録する matrix と、wall-time/RSS/disk reserve/停止条件を事前に固定する手順がない。依頼文 §15:852–895 の複数規模・分布に加え、限られた host 容量で安全に反復できる範囲を先に測る必要がある。R07 の manifest/validator にこれらの workload 軸、seed・fixture/asset hash、warm/cold、fault schedule、各 run の budget と preflight/途中 abort 条件を加え、出力に p50/p95/p99、throughput、RSS peak、DB/index/Graph disk、fanout/payload 実績と測定不能の理由を残す。件数・SLO 数値は**実測前に決めない**。R08 はこの matrix と想定業務量が対応した範囲だけ proposed SLO を作る。
