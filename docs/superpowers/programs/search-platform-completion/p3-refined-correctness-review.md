## Contract observations and limits

- **N-ary / delta:** `checked_relation` verifies ordinal completeness, participant multiset, reverse incidence and participant resources (`refinement.py:101-122`). The full audit compares the entire raw incidence set, so surplus entries cannot hide outside queried seeds (`run_refinement.py:51-57`). PG deletes old participant rows before same-ID relation replacement (`bench.py:157-186`); redb removes old participant and reverse-index keys before inserting replacement (`src/bin/refinement_redb.rs:158-239`); Neo inserts only unchanged and changed target-generation relations (`bench.py:263-272`). All three receipts show old same-ID and deleted incidence gone, new incidence present, and full/incremental digest parity. This tests the fixed fixture, not a general closure-proof or concurrent-build implementation.
- **Current Source authority:** `SourceAuthority` is a mutable, Source-scoped synthetic stand-in (`refinement.py:52-98`). Query checks each encountered participant through current revision and denies a relation before visible budget accounting (`refinement.py:135-199`). Source 1 revision 1 returns two hits; revision 2 revokes a participant and returns zero. Source 2 denies the same bare collateral ID and returns zero; its transcript shows four Source 2 access calls and no Source 1 call. Unknown/error at the seed both return zero. An additional fresh redb native probe changed a **non-seed participant** to Denied, Unknown and Error in memory; each returned zero and recorded that participant access. Document, FolderPlacement and Version mappings, owner-spoof and retention checks are against this fixture authority, **not** production Source truth or `DocumentCurrentAccessAdapter`.
- **Temporal / digest:** The fixture exercises negative and positive offsets, nanoseconds, `None` versus empty freshness basis, and one half-open end boundary (`make_refinement_fixture.py:92-105,156-158`). PostgreSQL reads five persisted numeric-nanosecond/offset pairs plus basis and compares them to payload (`refinement_backends.py:40-69`). redb and Neo4j store temporal in the resource payload; their tamper RED is a fixture-wide roundtrip mismatch, not an independent temporal-column check. `canonical_digest` is the versioned PoC logical JSON digest (`refinement.py:18-34`), **not** the planned P3-G02 production canonical encoder. Invalid offset/range and other categorical temporal rejection were not part of this 16-case fixture.
- **Negative cases:** All seven RED outcomes appear in each JSONL. Owner mapping spoof, `SessionOnly`, and `NoRetention` are common synthetic **pre-write** validator checks (`run_refinement.py:80-95`), not DB-enforced constraints. Missing participant and reverse incidence are native tamper detections. For PG and Neo4j the reverse-incidence tamper deletes the same participant row/edge, so it demonstrates missing-edge detection; redb additionally deletes its independent reverse-index key (`refinement_backends.py:86-102,152-173`; `src/bin/refinement_redb.rs:362-381`). Temporal tamper is caught by PG's separate columns and by fixture comparison for redb/Neo; persisted mapping tamper is caught at query.
- **Receipt boundary:** PG and Neo4j were not freshly executed by this reviewer. Their results are qualified by exact source/fixture/transcript hashes, native read/write code and saved actual-run assertions. The `oracle_binary_sha256` field is null after binary cleanup; I verified the checked-in generator source and the fixed oracle expectations, but did not rebuild the Rust memory oracle. Future qualification receipts should serialize a per-case actual path JSON hash so another reviewer can compare PG/Neo outputs without rerunning their services. No claim is made for multi-process publication, production READY immutability, roles, restore, or live Source authority.
