## Freeze を止める指摘

1. **[P1] Event 用 READY 候補の event/Source epoch 束縛が完了 transaction の必須条件になっていない。** draft:27 は `stage_event_id?`/`stage_source_epoch?` を任意列とし、draft:199 は同一 key READY/guard の照合を記すが、`PublishCandidate` に対する保存済み event ID と Source epoch の一致条件を列挙しない。P6 plan:21,189,198 は staging を event/epoch に束縛する。現行 outbox token と Source lease を持つ別 event が、過去 event または manual build の READY key を candidate として渡せる解釈を残す。event 用候補では両列を complete/non-NULL にし、`stage_event_id = outbox.event_id`、`stage_source_epoch = fence.epoch`、SourceId/key/snapshot/activation/guard の一致を同一 transaction で再検証する。manual build は明示的な別 origin とし、outbox completion へ渡せないよう DB 制約・private handle/port・role の境界を固定する。`ReuseCurrent` は現行 READY の再照合として別規則を明記する。実 PG RED/GREEN: `wrong_event_candidate_cannot_publish_or_write_receipt`、`old_epoch_or_manual_candidate_cannot_complete_event`、`reuse_current_requires_current_ready_after_gc`。
2. **[P1] Full guard は target に不変束縛されず、失効後の child write/READY を DB が拒む条件が不足する。** draft:31,122-129 の full guard は token/fence/expiry を持つが、`search_generation` 側に対応する不変 binding がない。draft:144 の child trigger は親 BUILDING のみを通常書込条件にし、draft:153 の READY transaction は full guard の token/fence/DB expiry を明記しない。draft:206 の「期限切れ token は再利用不可」を SQL/port で強制するため、P3 incremental target binding（P3 guard amendment:12-54）と同等に、full target の発行済み token/fence を不変に記録し、child write・READY・renew・publish を guard row と DB clock によって fence する。失効 guard の同じ target への再発行も拒否し、cleanup 後は新 generation key を発行する。実 PG RED/GREEN: `expired_full_guard_rejects_late_child_write_and_ready`、`full_target_guard_cannot_be_reissued`、`guard_delete_then_child_failure_rolls_back_full_target`。
3. **[P2] P3 `stage_full` と P7 の一 transaction 登録の呼出し境界を固定する。** draft:9,148 は Source → identity → P7/Graph generation → full guard を一 commit とする。一方、P3 plan:101,126-133 の `PostgresGraphStore::stage_full` は Graph BUILDING を作る公開 port であり、P7 の full handle を入力に持たない。Graph adapter に別接続・別 commit で同じ key を stage する経路を残すと、guard のない可視 Graph row または二重 INSERT が生じる。production の登録は P7 が所有する transaction-bound Graph repository method に限定し、P3 公開 `stage_full` はその登録済み handle に batch を追加する形へどう接続するか、また isolated P3 port と production path の境界を明示する。P3 selection 前は Graph 非依存の P7 行のみを許し、Graph READY は作らない。実 PG RED/GREEN: `full_registration_is_one_commit_with_guard_and_graph_key`、`graph_stage_failure_leaves_no_visible_unprotected_target`、`isolated_stage_full_cannot_publish_without_p7_guard`。
4. **[P2] durable pin の owner scope reference が SQL 形にない。** draft:32 は `search_evaluation_lease` に owner scope reference を要求するが、draft:130-139 の表は evaluation/key/activation/digest/expiry のみである。lease ID を所持する別 actor・旧 visibility revision・別 tenant の handle が `renew_pin`/`verify_pin_before_return` に渡された場合、保存行だけから発行先を再照合できない。tenant owner、registration/visibility revision と trusted actor/evaluation scope を指す非秘密の不変 reference を列に固定し、renew/verify/release は保存 reference、Source の現行 activation と P4/P5 current gate を照合する。actor の秘密・本文は保存しない。実 PG RED/GREEN: `pin_cannot_transfer_between_actor_scopes`、`registration_or_visibility_change_revokes_old_pin_read`、`foreign_tenant_cannot_renew_same_source_pin`。
5. **[P2] global ownership ledger の kind と Remote desired 集合の権威を schema/port で確定する。** draft:18-22 は全 tenant の Document/Remote を一 ledger に置き、Remote desired から欠けた Remote だけを tombstone、Document は維持すると明記する。ただし不変と書かれるのは tenant owner/SourceId で、`source_kind` の更新禁止と kind allowlist は SQL 形 draft:37-48 にない。また現行 P4 trait の `reconcile(&BTreeMap<SourceId, RemoteSourceRegistration>)`（`crates/search-application/src/remote_registration.rs:332-349`）自体は全 tenant・全 Remote の完全な集合を証明しない。Document 登録と Remote reconcile を同じ serial lock/ledger で行い、kind 変更・同じ SourceId の別 kind 再登録を拒否する。production adapter は host の revision と canonical full desired-set digest を、渡された DTO 全体（tenant/kind/registration/visibility を含む）と照合し、部分集合・旧 revision・同 revision 異内容を失敗させる。Document 行を Remote reconcile の対象から除外する条件を SQL で固定する。実 PG RED/GREEN: `remote_reconcile_never_tombstones_document`、`partial_tenant_map_cannot_tombstone_foreign_remote`、`document_remote_same_source_id_is_rejected_after_tombstone`、`partial_or_stale_remote_desired_set_is_atomic_failure`。
