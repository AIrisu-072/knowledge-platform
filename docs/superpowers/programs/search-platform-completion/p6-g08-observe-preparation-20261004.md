# G08：監視・トレース・配送ロールの最小実装（2026-10-04）

G07の合成PostgreSQL復旧2ケースの実証後、凍結計画のG08を実装しました。ここではソースと純粋テストの結果を記録します。実DBの監視・権限ケースは公開後のGitHub CIで確認し、その前にG08全体の合格を主張しません。

## 実装した範囲

- メトリクスのラベルを `route`・許可リストの `error_code`・有限の `outcome` に限定しました。本文、利用主体、Document・イベント・トレースのIDをメトリクスやDebug表示へ含めません。
- PostgreSQLの一つのDB時刻に基づき、実際の待機・処理中・打切り件数と最古行の経過時間を読み取ります。観測できない値を0で補いません。
- 実際に確認できた取得、配送確認、再試行、回収、古いフェンス、処理時間、DB・コンシューマーエラーを通知します。確定した `Lost` と、取消・タイムアウト・未完了I/Oの `Unknown` を区別します。
- 検証済みの親トレースから新しい子spanを作り、親がない旧行は新しいrootを作ります。Debug表示は識別子・stateを伏せます。通知先を設定しない既存Runnerに、追加の観測I/Oを発生させません。
- 既存の配送列だけを更新できるSQLテンプレートを追加しました。方針行の `FOR SHARE` に必要な `UPDATE(policy_id)` は、既存PK・NOT NULL・CHECK制約により値を変えない代入だけを許します。方針値、イベントの業務列、Document、Auditへの余分な権限は付与しません。

既存ポートには、任意のキュー観測とトレース読み取りを最小追加しました。実行時間、取消、リース・フェンス、結果不明を扱うG05/G06の境界を維持します。新しい依存関係、永続列、PostgreSQL設定、検証基盤は追加していません。

## 規範との整合と未計測項目

[W3C Trace Context §3.3](https://www.w3.org/TR/trace-context/#tracestate-header)に従い、不正な `tracestate` は破棄しても、正しい `traceparent` は保持します。従来のテスト草案にあった全体破棄の検証条件を、凍結設計の「W3C形式」という規範に合わせて修正しました。入力の長さ・形式の上限と、生のstateをログへ漏らさない条件は保持しています。

`CommitToAckLag` は宣言された13種類のうち、現在も未計測です。現行スキーマには生成側のcommit時刻が保存されておらず、`occurred_at` はイベント時刻です。この値や0をcommit遅延として代用しません。残る12種類は実際の観測値から通知します。OTLP exporterやcollectorの配備も、この変更には含めません。

SQLテンプレートは、他ロールの継承権限やPUBLICの追加権限を持たない、専用の非特権ロールを前提とします。実試験では一時DB内に `NOLOGIN` ロールを作り、実際の取得・観測・回収SQLを動かしたうえで、権限拒否のSQLSTATEを確認します。試験対象は架空データだけです。
