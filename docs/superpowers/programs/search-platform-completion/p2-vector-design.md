# P2 Vector / Embedding / Hybrid Retrieval v0 — design and qualification protocol

- Status: **DESIGN DRAFT / selection pending** (2026-09-30). This document defines the input, ports, evaluation and decision procedure. It does not claim that an embedding model, Rust runtime, vector engine, reranker, production dependency or deployment has qualified.
- Scope: P1 validated `KnowledgeUnit` → optional dense candidate generation → existing Search eligibility, S1 fusion and Discovery. P1 full body integration is a separate gate. Until it is live, synthetic/public Units with the identical frozen codec can qualify this design and harness, but cannot establish production body Search.
- Binding input: [`p1-knowledgeunit-freeze.md`](p1-knowledgeunit-freeze.md), which freezes [`p1-knowledgeunit-contract.md`](p1-knowledgeunit-contract.md) plus the precedence of [`p1-knowledgeunit-amendment.md`](p1-knowledgeunit-amendment.md). The parent-fixed [`p2-harness-first-contract.md`](p2-harness-first-contract.md) governs the first PoC slice; this design reconciles its scope and interfaces. `UnitId` is the unchanged nine-field, length-framed `ku1:` value; Archive uses the composite profile v2. No alternative chunk ID is introduced.
- Existing authority: [`Search design`](../../specs/2026-09-28-search-discovery-platform-v0-design.md) §§21, 27, 38, 50–54, 62; `spec/architecture/architecture-contract-v0.md` AC-08; `spec/selection/library-tool-selection-v0.md` §13.3; `crates/search-application/src/{ports,retrieval,discovery_service,federation}.rs`; [`P1 body amendment`](p1-body-absence-amendment.md). Source/current Read, P1 body evidence and S1 semantics remain authoritative. P4 remote retention rules are stricter where applicable.

## 1. Existing seams and invariants

`VectorRetrieverPort::retrieve(generation, request)` exists in `crates/search-application/src/ports.rs`, but supplies no explicit trusted query, model, window or bound Unit hit. The planner already has `RetrieverKind::Vector`; `DiscoveryService` invokes `CandidateFederator::merge(..., FusionStrategy::PriorityConcat)`. The production lexical and typed Graph paths provide real baselines. `Vector` therefore requires a typed extension at the application/adapter seam, not a second Discovery loop or a vendor type in `search-core`.

1. The embedding is a rebuildable representation of **P1 normalized `Unit.text`**, never a Source fact or authority. Preserve `ResourceVersionRef` (Version ResourceId, not DocumentId), `ContentPartRef`, `UnitId`, native locator, text digest, raw binding, representation, profile and the P1 generation binding. Unit-level retrieval folds to the existing parent Version `ResourceId` before the first reported retrieval ranking, with logical-resource grouping reported separately. Multiple Units of one Version do not become independent resources or independent evidence votes.
2. The existing S1 policy is routed retriever-order **priority concatenation** after hard eligibility, retaining per-retriever rank and raw score as trace only, and deduplicating logical candidates. Never add or compare heterogeneous raw scores. The Phase B eight-case sensitivity probe selected S1; its MRR is not a P2 quality measurement. Calibrated-score or RRF experiments are isolated variants and must not silently replace S1.
3. Similarity and ANN hits generate candidates only. They cannot prove exact text, `BodyRequired`, Source absence, authority, applicability or `Read`. P1 `KnowledgeUnitHitRef`/Source-owned exact resolver and the separate exact-negative proof remain the only relevant body-evidence paths. A Vector-only hit cannot satisfy the `BodyOnly` lexical seal or `document.body.contains_exact` predicate.
4. One evaluation pins one Source generation. Candidate creation and disclosure check the same immutable P1 `BodyUnitManifest`/bundle, current Source-owned `Read`, current Live Version/T10, authoritative Part/representation/raw, and retention permission. Denied and Unknown are fail closed, with ID-free gaps; recheck immediately before public result/trace. Historical lookup uses its existing explicit Version/`ReadHistory` path and does not silently enter the Live Vector index.
5. Vector is optional in routing and activation. A Vector failure, missing manifest, model mismatch or stale generation returns a bounded unavailable/unknown retrieval action, never an absence assertion or a mixed-generation rank list. The qualified lexical/Graph route remains usable where its own required evidence is sufficient.

## 2. Harness first: corpus, judgments and five real pipelines

The first deliverable is a **versioned, reproducible evaluation harness**, before a model or engine selection. A deterministic synthetic corpus uses the frozen Unit codec/normalization and P1 golden ID vectors. It contains Japanese and mixed Japanese/English query–Unit pairs with separately written judgments: exact finance/business terms and abbreviations, synonym/paraphrase, terminology crossing languages, tables/cells/slides/Archive locators, near-duplicate Versions and Parts, same wording in different scopes, graph role/path only, hard applicability mismatch, stale Version, revoked/Unknown Read, no relevant visible result, and long text at token limits. Include at least one query with **two or more eligible relevant parents**, one where a relevant parent is reachable only by the typed Graph route, and one with relevant Units in distinct Parts of the same Version. A query whose answer is in an unauthorized resource must have zero eligible qrels for that actor. Avoid customer names, real document bytes and credentials.

The public lane is a small, pinned Japanese slice of [MIRACL topics/qrels](https://huggingface.co/datasets/miracl/miracl) and its separately published [corpus](https://huggingface.co/datasets/miracl/miracl-corpus), with optional English pairs to exercise mixed-language retrieval. MIRACL publishes native-speaker judgments, but a sampled, closed corpus is **not** the official whole-corpus benchmark. Pin repository revision, exact selected IDs, source-file hashes, license/attribution, query/qrel split and mapping `docid → synthetic Source/Version/Part/Unit/locator`; fetch only needed rows/shards after byte-size preflight, do not run its arbitrary loading script, and do not import the full Japanese corpus. Check the corpus' underlying redistribution terms separately before committing text; if not cleared, store only a fetch manifest/hash and keep public bytes outside the repository. Public qrels are passage relevance, not proof of Source/Version/Read/Graph correctness. Synthetic strata retain that responsibility.

The harness input schema is immutable `corpus_manifest` + `units` + `queries` + `qrels` + `source_graph` + `access_scenarios`:

| Field group | Required contents |
| --- | --- |
| Corpus | generator version/seed or public revision and hashes; locale/domain/format strata; Source snapshot; P1 profile/build; raw/normalized text hash; Version/Part/Unit/native locator; allowed actor, retention lease; graph relation/role provenance. |
| Query | stable ID, text, intent/profile, Source route, actor, current Version policy, expected candidate window, one or more applicable relevance strata; label-author and label-freeze revision. |
| Qrel | query + **parent Version ResourceId** + optional logical-resource identity and supporting Unit(s), grade `0..3`, eligibility under the actor/time/Source snapshot, reason/evidence; all eligible positives enumerated within the closed corpus. A separate `unjudged` state is not grade 0. |
| Run | exact corpus/qrel/model/runtime/engine/port code digests, tokenizer/pooling/truncation/normalization, lexical analyzer/schema, Graph schema, generation, route and fusion policy, host and budgets, warm/cold mode, random seed, repetition schedule, license inventory. |

Freeze labels before seeing candidate ranks. A checker rejects duplicate/ambiguous Unit IDs or locators, missing parent binding, contradictory qrels, cross-scope labels, mixed generations, inaccessible positive labels, and incomplete public-slice judgment coverage. For a public subset, declare a closed judgment pool, adjudicate any newly found top-window candidates blind to method, and report unjudged rate; do not turn unjudged into negative labels. Split development and untouched holdout by query family and parent, so Version duplicates and paraphrases do not leak across splits. The synthetic label oracle is author-reviewed text/relation semantics, not the generated query token overlap or a model's answer.

Run these **real port** configurations on the same frozen corpus, pins, windows, eligibility and parent dedup (an all-mock rank-list test is insufficient):

| ID | Retrieval actions | Purpose |
| --- | --- | --- |
| L | existing real lexical adapter over the harness' bounded synthetic Source; P1 Unit/body wiring is a later vertical gate | S1 baseline and exact terminology; Unit locator integrity is checked separately until P1 integration |
| D | candidate embedding + exact dense scan first; ANN only as separate engine comparison | semantic candidate quality and index recall |
| LD | lexical + dense | incremental value and regressions versus L |
| LG | lexical + existing typed HyperGraph | graph-only rescue baseline |
| LDG | lexical + dense + HyperGraph | value beyond the already qualified Graph route |

`D` and combinations invoke actual embeddings and a real similarity search over `KnowledgeUnit`, not canned vectors. The existing Graph adapter must traverse its typed relation path rather than a prepared hit list. First verify L/LG on the same corpus, with explicit reporting that the P1 production body path is still pending; then add one model at a time. An optional reranker is an additional **post-candidate** arm over a predeclared small final set, never a substitute for retrieval recall. Record route order explicitly: the existing profile/planner determines S1 order, and adding D cannot reorder L or G without a separate reviewed policy change.

### Measurement and comparison

- At E0 check Version/Part/Unit/locator round trip, profile/raw/text hash, cache key, current access, retention, generation pin, incremental/full equivalence and failure rollback. At E2 measure deduplicated parent Version `ResourceId` `Recall@{1,5,10,20}`, `MRR@10`, `nDCG@10`, unit and logical-resource recall, and unjudged count; E3 reports graph-only rescue and false-composite cases separately. `Recall@K` denominator is **all eligible positive parent Resource qrels** in that query's closed corpus; `MRR` uses the first eligible positive; `nDCG` uses `2^grade-1` gain with `log2(rank+1)` discount and ideal eligible grades. Queries with zero eligible positives have undefined relevance ratios, are excluded from recall/MRR denominators and are reported as a separate false-positive/unauthorized-disclosure class. Report macro by query and by Japanese/mixed/finance/paraphrase/graph-only/access strata, not only one pooled score.
- For each arm, retain list rank, raw score **within that retriever**, excluded/pending gate reason, parent dedup and resulting S1 rank in an access-safe trace. Attribute misses to Source routing, candidate generation, ANN approximation, hard eligibility, fusion or qualification. Report conditional recall before and after each stage. A model that recalls a forbidden candidate is not a quality win.
- Measure end-to-end and stage-specific cold/warm `p50/p95/p99` query latency; embed query, similarity scan, Graph, fusion, authorization and disclosure separately. Use enough repeated queries for p99 to be meaningful and report sample count, concurrency, cache state and confidence interval; never present a p99 from fewer than 100 independently timed requests as stable. Capture **observed process RSS** (not a theoretical estimate), allocator/peak memory, model resident bytes, index/cache/disk bytes, model load, full build, units/sec, incremental add/change/delete, lease purge, rebuild/restart time and failed-build cleanup. The first harness slice uses bounded 32/256/1024-Resource synthetic scales from the early contract; report which completed under current contention and do not extrapolate an SLO. Index-quality reference is an exact scan on the **same embeddings and filters**; ANN `Recall@K` against this oracle is separate from semantic qrel recall.
- After pinning assets, block outbound network and repeat model load, query and rebuild to test actual offline/local operation. Record model/runtime/index license and transitive artifact notices, as well as replacement cost: re-embedding count/time/bytes, index rebuild time, manifest migration and rollback. A downloaded model card or an accepted API request does not prove these properties.
- Paired query deltas compare LD/LG/LDG with L and LG; pre-register priority strata and an uncertainty interval (query bootstrap for nontrivial sample sizes, exact per-case report for small synthetic fixtures). Record regressions, including finance identifiers, graph-only and access, rather than selecting a favorable aggregate. Raw scores are never summed. Only after S1 results, test a separate RRF or calibrated-rank arm using a development partition; fix parameters there, then evaluate once on the untouched holdout. A positive fusion result is a **proposal**, not an automatic S1 change.

## 3. Bounded candidate investigation, no production selection yet

Official source inspection on 2026-09-30 found two manageable, independently trained multilingual 384-dimensional candidates:

| Candidate | Official facts and required preprocessing | P2 test concern |
| --- | --- | --- |
| [intfloat/multilingual-e5-small](https://huggingface.co/intfloat/multilingual-e5-small/blob/main/README.md) | MIT; 384 dimensions, 12 layers; `query: ` / `passage: ` prefixes even for non-English text, masked average pooling and normalized embeddings; maximum 512 tokens. The published safetensors file is [471 MB](https://huggingface.co/intfloat/multilingual-e5-small/blob/main/model.safetensors). | Truncation of long Japanese Unit and financial terms; quality under correct asymmetric prefix. Do not silently concatenate neighboring Units. |
| [sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2) | Apache-2.0; 384 dimensions, mean pooling, model-card `max_seq_length` 128; its safetensors file is [471 MB](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2/blob/main/model.safetensors). | A distinct paraphrase-oriented comparison; check Japanese/mixed domain recall and short input limit. No E5 prefixes. |

[BAAI/bge-m3](https://huggingface.co/BAAI/bge-m3) (MIT, multilingual, dense output 1024, advertised 8192-token context) is a **larger optional escalation** after the small-model matrix and storage preflight. Only its dense mode is comparable to the two models above; sparse/multi-vector features would require separately named arms. These model-card descriptions are candidate facts, not local compatibility, business-domain quality or license clearance of all transitive assets. Pin exact model commit, safetensors/tokenizer/config hashes and downloaded file list before running. Do not use `main` as a runtime identity.

Rust inference candidates: [Hugging Face Candle](https://github.com/huggingface/candle) (Rust CPU/Metal, MIT OR Apache-2.0) and [`ort`](https://github.com/pykeio/ort) with [ONNX Runtime](https://onnxruntime.ai/docs/execution-providers/CoreML-ExecutionProvider.html) (CPU first; CoreML is a separately measured option). Rust integration, tokenizer parity, pooling/normalization parity, macOS arm64 binary/runtime footprint, exact ONNX artifact/export provenance and Linux CI portability need PoC. Prefer a pinned CPU/ONNX artifact when it fits; if ONNX export duplicates model weights, evaluate a pinned safetensors/Candle CPU path instead. Do not install default CUDA/PyTorch stacks merely for this comparison. Use the pinned model's reference output only as a **test-only numerical oracle**, then compare query/passage vectors and rankings against the Rust candidate; reference success is not Rust production qualification. No `POC REQUIRED` crate enters a production `Cargo.toml` at this stage.

Engine families for the same immutable vectors: (a) bounded in-process exact cosine/dot scan as the semantic and ANN oracle, (b) Rust [`hnsw_rs`](https://github.com/jean-pierreBoth/hnswlib-rs) with dump/reload/filter support as an in-process ANN candidate, (c) [pgvector](https://github.com/pgvector/pgvector) exact/HNSW/IVFFlat where PostgreSQL extension operation and generation isolation are feasible, and (d) [Qdrant](https://github.com/qdrant/qdrant) as a separate-service comparison only if scale/operations justify it. These are **comparison families**, not selected dependencies. Exact scan has no ANN miss and low operating cost at a small filtered corpus; ANN adds build/memory and recall tuning. pgvector uses the PostgreSQL license; `hnsw_rs` uses MIT/Apache-2.0; Qdrant declares Apache-2.0. Verify actual pinned releases, SBOM, security, license and native packaging before any promotion. The existing Postgres image does not establish that pgvector is installed; do not pull a new image merely to complete a paper comparison.

The observed local host is macOS arm64 / 16 GiB RAM. Disk free space changed from the earlier `environment.md` 12 GiB to 4.9 GiB in the parent-fixed early contract while other work ran; a subsequent `df -h .` varied between 5.1 and 6.1 GiB. **Do not download/build model weights now.** Before each later download/build, measure free disk and memory again; compute a per-candidate **peak** budget from actual remote file sizes + runtime artifacts + temporary conversion files + index/cache + existing build output. Reserve space for other active builds and OS operation, run **one** model/runtime/engine at a time, fetch only needed pinned files (not both PyTorch and safetensors or a whole dataset), and abort before crossing the recorded free-space floor. The floor and timeout are entered in the run manifest before execution from current host capacity; they are not tuned after a disappointing result. If a candidate does not fit, record `ENVIRONMENT_UNAVAILABLE` with estimated/observed bytes and continue the feasible pair; do not call it a quality failure. Start with the early contract's 32/256/1024 bounded Resources, then scale deterministically only while the declared memory/disk/time cap holds, preserving the same labeled core and reporting the last completed size. The small labeled quality corpus and larger capacity distractor corpus have different claims; avoid a million-document load without evidence that this host can sustain it.

## 4. Provider-neutral contracts and activation

The following are **proposed interface shapes**, not claims of current implementation. Keep vendor-specific inference/index types in adapters. `EmbeddingModelSpec` is a registered, immutable content-addressed definition: model name **and exact revision/weight hashes**, tokenizer files/revision and Unicode/input preprocessing, query/passage templates, pooling, token limit/truncation, output dimension, float precision, normalization/metric, runtime family/build/native binary and deterministic configuration. Its digest is `embedding_model_id`; any semantic or numerical change creates a new ID. Reject a vector with wrong dimension, NaN/Inf, zero norm when unit normalization is required, or a model ID that does not match the active index.

```rust
// Shapes only; use existing typed IDs and P1/P4 owner handles in production.
struct EmbeddingInput<'a> { unit: &'a KnowledgeUnit, binding: &'a PinnedBodyUnitBinding }
trait EmbeddingProvider: Send + Sync {
    fn spec(&self) -> &EmbeddingModelSpec;
    fn embed_units<'a>(&'a self, input: &'a [EmbeddingInput<'a>], budget: EmbedBudget)
        -> BoxFuture<'a, Result<Vec<BoundEmbedding>, EmbeddingError>>;
    fn embed_query<'a>(&'a self, query: &'a TrustedVectorQuery, budget: EmbedBudget)
        -> BoxFuture<'a, Result<QueryEmbedding, EmbeddingError>>;
}
struct VectorHitRef {
    generation: ProjectionGenerationKey, unit_id: UnitId,
    version: ResourceVersionRef, part: ContentPartRef,
    authoritative_representation_ref: String, raw: RawBinding,
    profile: ExtractionProfileId, text_sha256: [u8; 32],
    rank: usize, raw_similarity: f32, model_id: EmbeddingModelId,
}
trait VectorIndexPort: Send + Sync {
    fn stage<'a>(&'a self, source: &'a PinnedBodyBundle,
        spec: &'a EmbeddingModelSpec, units: &'a [BoundEmbedding])
        -> BoxFuture<'a, Result<VectorStageReceipt, VectorError>>;
    fn search<'a>(&'a self, pin: &'a PinnedVectorGeneration,
        query: &'a QueryEmbedding, filter: &'a TrustedVisibleScope,
        window: RetrievalWindow)
        -> BoxFuture<'a, Result<Vec<VectorHitRef>, VectorError>>;
}
// Existing VectorRetrieverPort remains the application-facing façade; add an
// explicit TrustedVectorQuery/window/result binding to its current weak seam.
```

`TrustedVectorQuery` is compiled/validated by the planner from an authorized request and is bounded in bytes/tokens/window; a caller cannot nominate an arbitrary model, principal, scope or Source. The façade must produce existing `FederatedCandidate`/`RetrieverRankList` plus internally preserved `VectorHitRef`; never serialize an unvalidated hit directly. It may prefilter with a coarse access projection for work reduction, but Source-owned current `Read` and binding checks remain mandatory before candidate visibility, fusion and disclosure. Stable tie breaking uses `(score descending, UnitId bytes)` within one model; across models only ranks can be compared in an experiment.

The P1 amendment's embedding cache key is the minimum: `(embedding_model_id, UnitId, text_sha256, ExtractionProfileId, source_id, authority_scope_key, retention_lease_id, lifetime_scope_id)`. Here `embedding_model_id` already includes weights, tokenizer, normalization and runtime revision. Store origin Version/Part/raw/representation and generation in the entry. On lookup, revalidate the current lease/retention and trusted Source binding; cross-generation embedding-byte reuse may occur only after the destination's permission check and **new** generation/parent binding. A cache miss, cache existence or similarity score cannot justify access or evidence. Keys, embeddings and model inputs are body-derived and must not enter telemetry or unauthorized backups.

Each `VectorProjectionManifest` records P1 pinned bundle key/receipt digest, Source snapshot and owner/retention lease, embedding spec ID, vector schema/dimension/metric/precision, index engine/build/parameters, extraction profile set, lexical analyzer/schema revision for the comparable bundle, Graph schema revision, sorted Unit binding/digest count, index receipt/digest, creation time and readiness. The analyzer is recorded for experiment and bundle comparability, **not** a Vector input or Vector cache-key component. Manifest validation enumerates built index entries in both directions against eligible P1 Units: no missing/extra/duplicate Unit, wrong parent/Part/locator/profile/raw/text/model/scope/generation. A `Partial` P1 item may contribute only its validated Units and cannot be called complete; `Unsupported`/`FailedPermanent` contributes none. Missing Units due only to retention prohibition are a separately recorded nonindexed set, not a false full-coverage receipt.

Build into isolated staging. Validate counts, bindings, hashes, permissions and exact/ANN reference behavior; activate a Vector pointer only by CAS against the still-current P1 generation and model/profile/lease. Queries pin the P1 bundle first, then a Vector manifest with the **same** key and valid owner lease, otherwise skip Vector. Failed/interrupted stage, publish conflict, model change or purge leaves the last valid P1/lexical/Graph pointer intact and discards only unpublished Vector artifacts. Old published Vector generations stay immutable for in-flight pins while current Source checks still suppress revoked results. On restart, recover the last fully validated Vector manifest or mark Vector unavailable and rebuild from Source/P1; never infer a ready index from orphan files. Full and incremental indexing use the same canonical sorted Unit set. Incremental handles add/change/delete and stale-version tombstones, rebinds reused bytes to the new generation, and verifies logical equivalence to a full rebuild at the same P1 snapshot; model/profile changes require full re-embedding. Record time/bytes for each path.

Retention is applied to **embeddings as body-derived artifacts**, regardless of whether discovery metadata may persist. `PERSISTENT_RESOURCE` requires explicit Source permission for persistent body embedding in that authority scope; `PERSISTENT_DISCOVERY_METADATA` does not grant it. `CACHE_WITH_EXPIRY` is bounded by the shortest Source/actor/session lease, and for P4 remote obeys its RAM-only owner rule. `SESSION_ONLY` stays in owner-gated RAM for that session; `NO_RETENTION` only in the current evaluation RAM. Both prohibit persistent index/cache/backup/queue and application-managed disk spill. Expiry, close, cancellation, revocation, scope change and error invalidate pending handles, cache and corresponding Vector entries. A remote Source's metadata retention is never treated as an embedding permit. If such owner-gated ephemeral operation is not implemented and tested, those Sources do not run Vector.

## 5. Decision gate and implementation slices

Before running the untouched holdout, write a decision sheet with priority queries, minimum meaningful quality delta, tolerated p95/p99/resource cost, and the current lexical/Graph baseline. Use business intent and measured baseline to set these, not post-hoc tuning. Adopt Vector only if LD or LDG shows a repeatable, attributable gain against **both** L and LG where relevant, without security/authority failures, material regressions in critical strata, or an unworkable build/update/operation cost. A tie, wide uncertainty, or gain only against a weak lexical arm yields `optional / disabled by default`. The provider-neutral port, corpus, reproducible results and runtime/index qualification still complete. Optional reranker requires independent added nDCG/MRR on the small qualified set, with its own latency and retention gate. A change from S1 to RRF/calibrated fusion requires a separate decision and contract update; raw-score addition is never a candidate.

Concrete scoped work, in dependency order (file names are proposed implementation artifacts, **not** edits made by this draft):

1. **Harness/labels** in isolated `experiments/search-vector-poc/{Cargo.toml,Cargo.lock,README.md,corpus_manifest.json,queries.jsonl,qrels.jsonl,src/{lib,validate,corpus,run,metrics,report}.rs,tests/{frozen_unit_codec,relevance,security}.rs,report.md}` with its own `[workspace]`; root Cargo files remain untouched. `validate_corpus()` checks exact frozen Version/Part/Unit/locator/profile/raw/text and UnitId goldens; `run_arm(arm, pinned, actor, window)` runs actual existing lexical and typed Graph adapters for **L and LG** under current Read/temporal/hard eligibility/S1; `score_run()` and `measure_run()` emit metrics and observed RSS/disk with methods/sample count. Fix the bounded public fetch manifest, query split and reproducible `prepare/verify` commands. First slice marks D/LD/LDG **UNRUN**, never zero-scored. It can start immediately from the frozen minimal P1 contract; production body integration remains a separate acceptance gate. Use bounded build settings (`debug=0`, `incremental=0`, jobs=2), retain receipts, and clean only owned disposable PoC output.
2. **Test-only embeddings** in the same PoC: two pinned candidates, exact similarity engine, reference-vs-Rust numerical parity vectors, prefix/tokenization/truncation checks, dense and hybrid runs on the identical pins/labels. No root `Cargo.toml`/`Cargo.lock` change until a selected adapter passes the dependency gate. Reject incorrect dimension/non-finite embeddings, mixed model IDs, different query/passage transforms and unreviewed automatic downloads.
3. **Engine comparisons** in isolated PoC packages: exact scan then one ANN family only when measured scale warrants it; compare ANN to exact on identical vectors and filters, add/delete/rebuild/restart/lease-purge and disk/peak memory. Test PostgreSQL extension availability before pgvector; do not turn absence of an installed extension into a candidate quality verdict.
4. **Application contract RED** in `crates/search-application` / `search-core` only after the P1 schema is integrated: trusted query and window; VectorHitRef-to-parent binding; S1 raw-score trace, hard eligibility and Graph-only preservation; stale/Unknown Read, Version/Part/raw/profile/model/generation mismatch; `BodyRequired` and exact-absence nonpromotion. Contract tests use a deterministic fake provider to force failure boundaries, while the PoC/vertical tests use real embeddings.
5. **Chosen adapter GREEN** in a separate `search-vector-*` adapter, plus scoped Source/P1 runtime wiring and typed configuration. Staging/CAS, receipts, full/incremental equivalence, TTL/revocation and crash recovery must pass with real storage. Keep model/engine specifics outside Domain/Core. Independent architecture/security review, dependency/license audit, focused vertical tests, then exact-head hosted gates and acceptance receipt precede any production selection claim.

The qualification report distinguishes `SOURCE_INSPECTED`, `HARNESS_PASS`, `MODEL_QUALITY_MEASURED`, `RUST_PARITY_PASS`, `ENGINE_PASS`, `PRODUCTION_INTEGRATED`, `HOSTED_PASS` and `SELECTED`/`DISABLED`. A model card, HTTP 200, or synthetic mock test only establishes its own stage. No result in this design draft is a measured P2 qualification.
