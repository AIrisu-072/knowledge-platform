## Blocking findings

1. **[P1] synthetic の部分 `Vec` を通常の公開 API から actor-visible catalog にできる。** `SourceRegistrationCatalog::try_new_synthetic(Vec<RemoteSourceRegistration>)` と `try_new_synthetic_with_ledger(..., Vec<...>)` は通常 build で `pub` のまま、`SourceRegistrationCatalog` を返す (`source_registration.rs:1138-1178`)。`replace_synthetic_checked(Vec<...>)` も通常 build で `pub` (`source_registration.rs:1226-1247`)。`TrustedVisibleRegistry::new` はその catalog と durable ledger の catalog を型で区別しない (`source_registration.rs:1322-1338`)。したがって production composition code が tenant 別の部分 `Vec` を渡し、synthetic host がその集合を「全 Remote」として publish しても、同じ actor-visible port が組み立つ。これは P4 追補 §2/§3 (`p4-source-neutral-implementation-amendment.md:75,83,89`) の「complete desired は trusted host の全 tenant snapshot のみ」「production 経路は部分 desired を渡せない型」と graph acceptance に反する。コメントと `synthetic` の名称は compile-time の禁止にならない。**修正:** 三つの公開 Vec convenience method を通常 build の production API から除く。legacy 13 test は test 側 helper が独立 synthetic host authority に complete Document/Remote snapshot を publish し、`CompleteDesiredRegistrations::capture` → 正規 `try_new` / `replace_checked` を通す。synthetic ledger trait 実装の意図的な注入は別の trusted composition / P7 factory gate として検証する。
2. **[P2] 内部 scope 構造不一致を client request error に分類している。** `TrustedVisibleRegistry::visible_sources` は bind 結果の actor/Source が列挙対象と違うと `SearchError::InvalidRequest` を返す (`source_registration.rs:1361-1364`)、新規 test もそれを期待する (`source_neutral_catalog_contract.rs:1058-1069`)。P5 改訂 2 はこの構造的不一致と registry/visibility error を四 route 共通の generic `503 DEPENDENCY_UNAVAILABLE` と定める (`p5-api-contract-revision-2.md:59`)。`InvalidRequest` は公開入力の検証にも使われる (`error.rs:4-10`) ため、後続 wire mapping に誤った 4xx 分類を持ち込む。**修正:** scope 不一致を固定・ID-free な `SearchError::OperationFailed` に変え、新規 test の期待 variant を更新する。P5 handler ではこの port 境界の全 error が generic 503 に落ちることを別途確認する。

## 確認できた範囲

- `TrustedSearchScope` / `AuthorizedSourceScope` の既存 mint を Document と Remote で共有する。`SourceRegistration::{Document,Remote}` の descriptor は variant から導出し、union catalog は同一 `TrustedVisibleRegistry` を通る (`scoped.rs:113-204,207-242,502-584`; `source_registration.rs:280-351,1320-1395`)。第二の mint/ledger は対象六ファイルにない。

- actor は列挙前後、Source は bind/current/activation で確認する。Source 固有 Denied/Unknown/revision 競合は除外、port error と構造的不一致は成功一覧を返さず全体 error とする (`source_registration.rs:1342-1395`)。unknown commit は local current gate を閉じる (`source_registration.rs:1184-1223,1267-1317`)。安定 stamp の証明がないため `continuation_stamp=None` (`scoped.rs:255-277`; `source_registration.rs:1392`)。
