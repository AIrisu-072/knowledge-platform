# P4 Remote Source — independent architecture review

- 判定: **NO-GO（設計凍結前に P1/P2 を解消）**。
- 対象: `p4-remote-design.md` と Search / Discovery v0 承認設計、関係する `spec/`、現行 `search-core` / `search-application` の Port と Discovery 経路。設計・コードの静的照合のみ。実装・通信試験・本番適合の判定ではない。

## Findings

1. **[P1] 1 Source に複数の評価内 generation を割り当てる場合の Federation 契約が未定義。** Draft §3 (`p4-remote-design.md:85`) は action ごとに新しい key を作り、同じ Source の以前の snapshot と併存させる。一方、`CandidateFederator::validate_lists` (`crates/search-application/src/federation.rs:122-145`) は同一 Source の異なる generation を `MixedSourceGenerations` で拒否する。`DiscoveryService::evaluate` も Source 単位の `pin.key` を全 list、重複排除、Claim 解決に使用する (`crates/search-application/src/discovery_service.rs:553-639`)。複数 mode を持つ Source では、現案のまま実 E2E が qualification に到達しない。**修正:** action/list/hit の snapshot key を全評価段階へ通す設計を明記し、Federator の「durable Source は単一 pin」を保ちながら remote action の複数 immutable key を許す条件を定義する。同じ Resource の別 snapshot/version を無検証で一つの Claim や binding に混ぜない規則と回帰例を追加する。

2. **[P1] trusted tenant/principal と既存 Discovery の access context の結合が不足。** Draft §2–3 (`p4-remote-design.md:19,37-43,83,89`) は request-scoped registry と `TrustedRemoteContext` を置くが、現行 `DiscoveryService::discover` は `DiscoveryRequest.access_context: String` を受け、引数なしの `SourceRegistryPort::list_sources()` と設定済み `RoutingConstraints` で route を作り (`crates/search-application/src/discovery_service.rs:167-179`, `crates/search-application/src/ports.rs:39-42`)、最終 access 判定にもその文字列を渡す (`discovery_service.rs:506-519`)。Source access が拒否されても route の Source ID は `source_trace` / gap に出得る (`discovery_service.rs:721-731,814-839`)。**修正:** P4 自身の service 境界で trusted tenant/principal/session と request の binding を検証し、required/preferred Source を含む registry と route を認可済み範囲へ限定する。Remote Port、current access/policy、最終可視性判定は同一の trusted binding を使う。Source-scope Denied/Unknown 時の trace/gap は存在を漏らさない形へ正規化し、別 tenant/principal の access context 差替えと Source ID 指定の回帰を acceptance に入れる。P5 transport の実装待ちにしない。

3. **[P2] ephemeral / LIVE_ONLY candidate が共通 qualification に入る条件が未定義。** Draft §3 (`p4-remote-design.md:87`) は安定 ID のない provider を `EphemeralCandidate` とするが、現行 `DiscoveryService::evaluate` は `resource_ref == None` の candidate を qualification 前に `continue` し、`QualifiedResource` は `ResourceId` 必須 (`discovery_service.rs:612-640`, `crates/search-core/src/discovery.rs:93-104`)。`ProbeExecutionService` も ID なし ephemeral target を unsupported にする (`crates/search-application/src/probe_execution.rs:52-57`)。**修正:** P4 が ephemeral を qualified result として扱うなら、評価内だけの ResourceId/projection と current access/evidence lookup、binding 禁止、終了時破棄を設計に定義する。扱わないなら明示的な unsupported/gap とし、「全 mode の qualified E2E」と混同しない。`LIVE_ONLY` の再取得時に同一 candidate identity へ無条件に内容を再結合しない。

4. **[P2] expiry と NO_RETENTION の実際の所有期間が契約化されていない。** Draft §3–4 (`p4-remote-design.md:85,99-103`) の `RemoteSnapshotSet` は「evaluation/session expiry」で破棄とする一方、`NO_RETENTION` は評価呼出し RAM 限定とする。既存 `SessionWorkingSet` は owner、deadline、TTL を持たず、materialization receipt を保持できる (`crates/search-application/src/session.rs:35-56,199-228`)。**修正:** snapshot/store を retention 別に分け、`NO_RETENTION` は成功・error・cancel のすべてで evaluation 終了時破棄、`SESSION_ONLY` は trusted session owner と絶対/idle expiry、`CACHE_WITH_EXPIRY` は provider 上限 TTL と access revision を、各 read/write 時に検査する契約にする。close、期限切れ、revocation 時に projection、Graph、probe、receipt、materialization bytes を一括無効化する。期限切れ後に保持した参照から再読できない試験を追加する。

5. **[P2] provider 由来 Evidence の direct / independent 判定を信頼済み情報へ固定する条件が不足。** Draft §3 (`p4-remote-design.md:75-89`) の `RemoteHitBundle` は `ResolvedAssertionEvidence` を受け、assertion の `Authoritative` 昇格を制限する。しかし core の `is_verified_direct_claim_evidence` は `role`、`is_summary`、非空の `upstream_origin` だけで direct と判定し (`crates/search-core/src/evidence.rs:57-69`)、sufficiency は origin 文字列の distinct 数を数える (`evidence.rs:219-242`)。`assemble_resource_claims` は Port の返す値を使用する (`crates/search-application/src/evidence_resolution.rs:87-123`)。**修正:** provider JSON の role/origin をそのまま `ResolvedAssertionEvidence` に写さず、registration と検証済み provenance から adapter が role・canonical upstream lineage を付与する規則を明記する。同一 upstream の別ラベルを独立 corroboration と数えない例、未検証 provenance が `Unknown` に留まる例を acceptance に追加する。

## Confirmed direction and remaining boundary

- Remote query miss を absent/deletion にしない方針、complete sweep / authoritative direct lookup だけの `VerifiedAbsence`、outage と Resource state の分離は承認設計 §18 と `spec/data/transaction-consistency-requirements-v0.md:1065-1072` に整合する。
- 永続 store と evaluation RAM を分け、`PersistableGenerationManifest` / `PersistableResourceProjection` の現行 retention gate を保つ方針は妥当 (`crates/search-application/src/projection.rs:269-329`)。metadata-only の field proof を先に追加する必要も Draft に明記されている。
- credential-free の loopback HTTP provider を `DiscoveryService::discover` まで通す acceptance、SSRF の接続先 pin / redirect 拒否 / 応答サイズ上限、current access の再検査は設計上の適切な必須条件。上の findings を修正後、実通信・期限切れ・ACL 変更・retention 漏洩の試験で初めて P4 実装の達成を判定できる。
