## PostgreSQL build reproducibility warning

The already-built **P7 functional-test** prefix at `/workspace/shared/search-toolchain/postgres` is *not* a P3 candidate binary. Observed `postgres --version` and `pg_config --version` are both 18.6; `pg_config --configure` reports `--prefix=/workspace/shared/search-toolchain/postgres --without-readline --without-zlib --without-icu`. It was built with GCC 14.2.0 on Debian 13 x86-64. Its currently observed binary hashes are `postgres` `a26f33c78c9bb1e6fe875b55e1a0ae640b45fd53c44174733471a26d707dca33`, `pg_config` `ad20857ade136be241b4ff82e739ffd0ac81535e67d73ca9a41702cfd5d8a8b2`, `pg_dump` `b05d0002edd213a8997b1b81fea1c75fdc0cfe8ad9731401293608fda9f91ec9`, and `pg_restore` `2ac40507e9110fcc56ca9ca3498fc8b779ca445a590e456cf7b195d3129deaaa` (SHA-256). They are identification evidence only, not a P3 pin or permission to retune/reuse that prefix.

The [PostgreSQL 18 build requirements](https://www.postgresql.org/docs/18/install-requirements.html) state `--without-zlib` disables compressed `pg_dump` and `pg_restore` archive support. Because P3 predeclares `pg_dump -Fc`/`pg_restore`, a separate isolated P3 prefix must predeclare build compiler/flags/options and include zlib support if compressed custom archives are used; do not silently substitute the P7 prefix or alter the recovery gate. The separate build still needs exact `pg_config`, server/client binary and linked-library hashes, locale/collation/ICU choice, backup/restore behavior proof and independent admission. PostgreSQL [source-build guidance](https://www.postgresql.org/docs/18/installation.html) governs the build procedure.
