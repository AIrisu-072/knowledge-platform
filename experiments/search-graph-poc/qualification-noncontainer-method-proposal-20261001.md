# P3 noncontainer qualification methodology — proposal, 2026-10-01

**Status: PROPOSED, not admitted for measurement.** This is a prospective environment-only adaptation because the dot cloud executor has no Docker. It does not edit `qualification-method.md`, the P3 freeze, the fixed fixtures, or any already recorded measurement. An independent methodology GO and controller admission are required before using this route for P3-P04 selection. The source-built PostgreSQL 18.6 instance prepared for P7 functional DB tests does not itself qualify any P3 timing, restore or publication gate.

## Unchanged gates

- Keep seed `314159`, the pinned 100/1,000/3,000-group base fixture SHA-256 values in `qualification.py`, 16-case actual MemoryGraphRetriever oracle, all three candidates, native full/incidence/Source/retention audits and all negative/fault scenarios. Regenerate absent ignored base fixtures only through the locked `src/main.rs make` command and accept them only on exact SHA match.
- Keep six query classes, 200 **successful raw** samples in every cold/warm × 1/2/4/8 readers plus one active incremental writer cell. There are 48 cells/profile/backend, 432 cells and 86,400 accepted samples overall. Preserve native request/read-transaction and no-OS-cache-reset disclosures, raw per-sample nanoseconds, writer overlap, percentiles, build/update durations, disk, RSS and lock-wait measurements. A missing or failed cell remains `UNMEASURED`/`Blocked`.
- Keep exclusive CPU window, no overlapping Cargo/model activity, 30-second cell and five-minute profile canaries, 2 GiB start floor, 1.5 GiB stop floor, 512 MiB 100-group candidate growth bound, and separately accepted measured-peak admission for 1,000/3,000. These are safety bounds, not SLOs. Retain raw logs, reports, transcripts, source/binary/fixture/environment hashes and the prior Mac/container receipts unchanged.
- Keep process restart, separate restore, corruption/missing reverse incidence/current-Source drift/failed-stage cases for each candidate. Keep PostgreSQL's actual accepted P7 physical-schema Source guard/READY/pointer/evaluation pin/GC and concurrency matrix. A surrogate table, PG-only functional test or Neo4j/redb missing atomic protocol is never a publication PASS. Keep independent license/operational assessment and comparative selection GO; `select_backend` stays `Blocked` until all hard gates pass.

## Exact acquisition pins before any download or run

1. A separate acquisition record must identify the **official PostgreSQL 18.6 source archive URL and publisher SHA-256**; the exact tarball bytes; build compiler, flags/options, linked libraries, locale/ICU and server/client binary hashes. Validate `postgres --version`, `pg_config --configure` and `pg_config --version`. Build only into an isolated task-owned prefix; do not replace or retune the P7 functional instance.
2. It must identify the **official Neo4j Community 2026.09.0 Linux distribution** and official checksum from Neo4j Deployment Center, exact archive bytes, bundled GPLv3 notice, official supported Java 21 distribution/version/checksum and Java binary hash, plus the unpacked Neo4j binary/JAR manifest and config hashes. Verify Community edition/version at runtime and local Query API v2 response. Neo4j documents noncontainer Linux tarball installation and Community offline dump/load; the exact Community archive and Java pin have not been acquired or approved in this proposal. Enterprise or another release is not an implicit substitute.
3. Pin redb `=4.3.0` through the isolated `Cargo.lock`, exact compiled binary and linked code-source hashes; Python `psycopg[binary]==3.2.10`; all three fixture hashes and actual Memory oracle binary hash. Approve the collected pin list in a separate controller/adversarial review receipt **before** candidate acquisition or execution. If an official archive/checksum/version or acceptable license cannot be established, mark that candidate `UNMEASURED` and selection `Blocked`.

## Noncontainer runtime substitutions

| Existing container proof/operation | Proposed noncontainer equivalent, with separate implementation and negative tests |
| --- | --- |
| `docker image inspect`, fixed image ID/digest | Official archive and publisher checksum, unpacked/build binary hashes, version and build/config manifest. Every report labels `runtime_mode=noncontainer` and includes this pin set; never presents it as the historical image ID. |
| `owned_container` label/name/mount and `docker port` | One task-owned private root per backend/profile with `.owner` marker, exact executable/config hashes, PID plus process start identity, private data and backup dirs, dynamically bound loopback port, liveness and version checks. Reject foreign/mismatched processes, data dirs or occupied ports before stage/cleanup. No global service or shared P7 PG reuse. |
| Docker `--memory` and `docker stats` | Explicit process-tree/RSS and disk metrics at admission, after staging and after each cell; enforce the same candidate and host floors with the actual OS facilities available. Record where a container memory ceiling has no exact noncontainer equivalent and stop rather than infer one. |
| `docker restart`, `docker exec pg_dump/pg_restore` | Stop/restart the exact owned PostgreSQL postmaster and rebind a verified loopback port; perform `pg_dump -Fc` and `pg_restore --single-transaction --exit-on-error` into a different private database using the pinned client binary. Verify full rows/Source/16 oracle cases and record backup hash. Preserve separately predeclared abrupt-process recovery/fault case. |
| Neo4j container stop and `neo4j-admin` in same image | Stop the exact owned Community process, perform offline `neo4j-admin database dump`, load into a **different** private installation/data dir using the same pinned distribution/Java, start it independently, then verify full rows/Source/16 oracle cases and backup hash. Do not use an online Enterprise-only backup path. |
| `stop_on_disk_floor` container cleanup | Stop only the verified PID/process tree and quarantine only matching task-owned paths after hashes/receipts are retained. Do not kill an arbitrary listener, remove shared Docker data, or delete the P7 functional DB. |

`qualification_driver.py`, `qualification_runtime.py` and `qualification_recovery.py` currently hard-code Docker ownership, stats, restart, port and backup paths. A new mode must fail closed unless every noncontainer ownership/pin precondition is satisfied. Add focused tests for wrong binary/version, wrong owner/PID, occupied port, failed restart, wrong restore directory, missing checksum, missing raw artifact, capacity stop, and omitted publication probe before enabling the mode. Keep historical report hashes and old source maps immutable; new reports include this amendment's hash and new source hashes.

## Comparability and decision boundary

Run **redb, PostgreSQL and Neo4j sequentially on the same dot cloud host** with pinned fixtures and a stable environment. The Mac redb100 48-cell/9,600-sample result remains valid historical evidence but is not a same-host performance comparator to new cloud PG/Neo data. Rerun redb100, then all three candidates at all admitted profiles on this host for cross-candidate performance claims. Record CPU/OS/architecture/compiler/runtime/config and time-window differences, including noncontainer vs original containers. If host resources cannot satisfy a profile, retain completed data but leave that profile and selection `Blocked`; do not weaken the matrix, infer missing samples or call the old Mac result an equivalent cloud run.

An independent review may approve this environment-only method under the already authorized autonomous P0–P7 program **only if** every frozen semantic, safety, evidence and selection gate above remains intact. The previous P3 methodology decision was autonomous, and P3 plan expressly requires no intermediate human approval. Frozen semantic change, gate removal, new production dependency, alternative non-PG publication protocol, material security/business tradeoff, licensing/legal blocker, irreversible production migration, merge or deploy is a Hard Stop for a separate user decision. This proposal grants no acquisition, run, backend adoption, production migration, merge or deployment by itself.
