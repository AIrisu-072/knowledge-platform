- `src/refinement_oracle.rs` generated all 16 ordered expected results by invoking the actual `MemoryGraphRetriever` with the fixture's Source-specific access decision for each case. The fixture stores those expectations. `tests/test_refinement.py` checks the Python traversal against this fixed oracle as a preflight; candidate results below came from their native persisted incidence and resources. The oracle binary was cleaned with the owned build cache before final reruns, so `oracle_binary_sha256` is null in the receipts; oracle source SHA-256 `3e390cd489872011007510e38c2362836e6dcd1961b8d6ed2fe07fdf3ead21c0` and final fixture bytes remain pinned.
- Each candidate scopes reads by `(Source,generation)`, expands from native `(resource,role)` incidence, reads every participant row/edge for each visited relation, checks it against the canonical relation payload and verifies reverse incidence and participant resources. Four whole-generation audits enumerate all resource IDs, relation IDs and raw incidence entries, compare them with the fixture, then compute a generation-independent logical digest over complete Resource mapping/temporal content and canonical typed relations. This PoC digest is not the future production G02 encoder.
- Scenarios exercise repeated role/n-ary exact paths, false composite, two hops, high hidden degree with visible budget, typed List qualifier and same-ID participant replacement, relation-only addition/deletion, negative `-04:30` nanosecond and positive offsets, `None` versus empty freshness basis, half-open time boundary, Source 1 revocation/Unknown/error, Source 2 same-ID denial, and Document/FolderPlacement/Version identity mapping. A mutable Source authority is reread per query; all persisted participants must be currently visible before a relation expands. The authority here is a Source-scoped synthetic fixture, not a production Source service.

## Reusable runner and remaining gate

`refinement_backends.py` exposes narrow `RefinedPg`, `RefinedNeo` and `RefinedRedb` methods: `neighbors`, `relation`, `resource`, `all_ids`, `incidence_rows`, scoped stage operations and deliberate corruption hooks. `run_refinement.py` is the stable fixed-fixture correctness CLI; its JSONL holds every stage/audit/query duration, access-call set, transaction outcome and intentional negative result. Later measurement can use this adapter interface without changing the semantic comparison path.

**P3-P04 selection remains Blocked.** A separate predeclared run must collect at least 200 raw samples per query class, cold/warm 1/2/4/8 readers plus writer, the restart/restore/fault matrix for all candidates, PostgreSQL shared publication/pin/GC/build-guard disposable probe, license/advisory qualification and independent selection review. Those measurements and production coordination/READY/role/lease gates have not been executed by this refinement. No backend has been promoted to production and the old 100/1,000/3,000-group durations remain historical subset data.
