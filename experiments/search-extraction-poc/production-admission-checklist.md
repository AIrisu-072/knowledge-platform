## Q01: bounded profile, native/license, and measurement gate

- Pin a registered profile per admitted format/setting, including parser source/binary hash, exact native PDFium hash where used, charset/dialect, scope/segmentation/normalization/locator revisions, and all archive outer/nested/leaf `ArchiveReaderNode`s. Changing any of these requires a new profile and rerun. The current PoC reports a runtime source-bundle hash and a separate binary hash; it does not produce a trusted production profile registry or full reader-use graph.
- Exercise all 15 budget keys at and immediately over their profile ceilings: `InputBytes`, `ZipEntries`, `ZipEntryBytes`, `ZipTotalBytes`, `ZipDepth`, `Units`, `UnitUtf8Bytes`, `WorkerOutputBytes`, `XmlDepth`, `XmlNodes`, `PdfPages`, `PdfOperations`, `HtmlNodes`, `CsvRecords`, `CsvFieldBytes`. The plan's maximum initial ceilings are 256 MiB input, 20,000 ZIP entries, 64 MiB/entry, 512 MiB expanded, depth 3, 100,000 Units, 1 MiB/Unit, 16 MiB result, XML depth 256/nodes 2,000,000, PDF pages 1,024/operations 1,000,000, HTML nodes 2,000,000, CSV records 1,000,000/field 1 MiB. Worker AS ≤2 GiB, scratch ≤1 GiB, wall ≤10 s, CPU ≤8 s. Non-applicable keys are 0. Verify pre-admission, during parsing, and host-result checks agree; an over-limit run yields no partial positive Units.
- Measure 1/10/50 MiB representatives **by format** plus max Unit, many small ContentItems/Parts, and high-ratio compressed ZIP in cold/warm runs. Record wall/CPU, RSS or cgroup high-water, scratch/output bytes, Unit counts, index build and query p50/p95/p99, unique-Resource fulfillment, worst cases, refused/unmeasured cases, source/lock/native/environment hashes. No unmeasured production SLO claim.
- Keep the actual external `cargo-deny` check and native PDFium distribution/license/security review separate from each reader row. The current PoC scan passed under cargo-deny 0.20.2 with non-blocking duplicate/unused-allow warnings, but that is only the current isolated lock. Re-scan exact selected dependency/profile inputs before production adoption. `license_security: not-executed` in JSON is intentional.
- Obtain independent read-only review of the expanded manifest, raw oracle, source/binary/native pins, adversarial failures, resource data, and candidate-vs-production boundaries. A failed format stays `Unsupported` while a separate candidate is qualified in this isolated PoC.
